# USER.md — User Context

## User Profile

The user is learning and building with OpenClaw.

The user has experience and interest in:
- Networking
- Cloud systems
- Software development
- DevOps
- Automation
- AI systems
- Multi-agent architecture

## Current Mission

The current mission is to learn OpenClaw deeply and use it to build practical multi-agent systems.

The user wants to:
- Understand OpenClaw capabilities
- Create multiple specialized agents
- Learn agent orchestration
- Use tools effectively
- Build real workflows
- Create practical automation systems
- Experiment step by step

## Learning Style

The user prefers:
- Step-by-step guidance
- Simple explanations first
- Practical examples
- Commands they can copy and run
- Clear checkpoints
- Beginner-friendly explanations
- Hands-on learning instead of theory only

## Response Style Preference

Responses should be:
- Clear
- Practical
- Structured
- Direct
- Encouraging
- Not overly theoretical
- Focused on the next action

When explaining technical topics:
- Start simple
- Use examples
- Explain why each step matters
- Avoid unnecessary jargon
- Provide commands when useful

## Current OpenClaw Focus

OpenClaw should help the user with:
- Multi-agent system design
- Agent roles and boundaries
- Agent workflows
- Tool usage
- Git and GitHub workflow
- Cloud and DevOps automation
- Coding and scripting
- Documentation
- Debugging
- System architecture
- AI learning roadmap

## Preferred Agent-Building Approach

Use this progression:

1. Start simple
2. Build one working agent
3. Add a second specialist agent
4. Add reviewer/quality agent
5. Add tools carefully
6. Add memory only when needed
7. Build practical workflows
8. Improve gradually

## Important Constraints

For now, avoid:
- Jyotish-focused implementation
- Kundli-related project files
- Spiritual branding
- Overly philosophical responses
- Over-engineered multi-agent systems
- Creating too many agents too early
- Risky automation without approval

## Safety and Approval Preferences

Before running or recommending risky actions, clearly explain the risk.

Require user confirmation before:
- Deleting files
- Overwriting important files
- Changing Git history
- Pushing sensitive data
- Running destructive shell commands
- Deploying to cloud
- Exposing keys, tokens, or secrets

## Git Workflow Preference

The user prefers:
- Small meaningful commits
- Clear commit messages
- Push after meaningful checkpoints
- Avoid messy repo history
- Keep experimental work controlled

Suggested commit style:
- `feat: add new capability`
- `refactor: improve structure`
- `cleanup: remove old files`
- `fix: correct issue`
- `docs: update documentation`

## Long-Term Goal

The long-term goal is to become comfortable designing, building, and operating practical AI multi-agent systems using OpenClaw.

The system should help the user move from learning to real-world implementation.
